# CRYSTAL STORY 移植仕様

原典：マイコンBASICマガジン 掲載「CRYSTAL STORY」（MSX2用 / 作：永山治）。
ジャンルは「詰めペンゴ」系の一人用パズル。本ドキュメントはJSへの移植時の挙動仕様としてまとめたもの。

---

## ゲーム概要

- グリッド上で「自分（玉ねぎ）」を動かし、盤面に置かれた「クリスタル（水晶玉）」を縦または横に3つ並べるとクリア。
- 並びは **縦か横のみ**。**斜めは不可**。
- 外枠に接する形での3連は **クリア扱いにならない**。
- 全 **30面**。30面クリア後におまけの2人用ゲーム。

## 画面構成（オリジナル）

- SCREEN 5（256×212、16色中4色＋パレット差替）。本移植もこの解像度を維持し、整数倍スケールで表示する。
- 1タイル = 16×16ピクセル。盤面は最大14×12タイル程度。
- 盤面の外枠はLINE BFで黒塗り。下端に `STEP n ROUND m` の1行ステータス。

## 操作

| 入力 | 動作 |
|---|---|
| カーソルキー | 自分を1マス移動（押す方向にブロック/クリスタルがあれば押す） |
| `G` | ゲームを諦めてタイトルに戻る（クリア不能になったとき用） |
| `C` | タイトルでの選択。コンティニュー（FC=1で同じ面を再挑戦） |
| 任意キー | タイトルから本編開始 |

スマホ向けには画面下に十字＋Gボタンを画面上に重ねる方針。

## 移動・押し出し仕様

`KS(x, y)` が仮想画面の各セル値：
- `0` = 空
- `1` = ブロック
- `2` = クリスタル

1ステップの判定（BASIC 行640〜720 相当）：

1. 入力方向に対し、隣接セル `SK = KS(X+X1, Y+Y1)` を取得。
2. `SK == 0` → 自分が1マス進むだけ。何も消費しない。
3. `SK != 0` → 押し出し処理に入る（`FS = SK`）。自分は移動しない。
   - 押す先のセル `(X+2*X1, Y+2*Y1)` が **盤外** または **空でない** 場合：
     - **ブロック**（SK=1）→ その場で **壊れる**（破壊アニメ＋効果音、KSは0に）。
     - **クリスタル**（SK=2）→ **跳ね返らない**。動かないだけ。
   - 押す先が盤内かつ空：
     - そのオブジェクトを **一気に滑らせて** 押し出し方向の次の障害物 or 盤端の直前まで進める（行760〜820のループ）。
     - クリスタルの場合、滑走中に `SX/SY` 座標配列を更新（揃い判定用）。
4. 自分が動かない押し出し動作（`FS != 0` の間）は1ステップ消費 `S2 += 1`。`S2 > S1` で `GO = 1`（クリア不能フラグ）。
5. 自分だけ動いた移動（空マスへ歩いた）は **ステップを消費しない**。

> ※「ブロックを飛ばす／壊す／クリスタルを飛ばす」のいずれも一手 = 1ステップ消費。

## クリア判定（行840〜890）

押し出しが落ち着いた直後、クリスタル3つの座標 `SX(0..2), SY(0..2)` を見て判定する：

- 3つのクリスタルのうち2つでも `(0, 0)` 端寄り/`(XM, YM)` 端寄りで完全に外枠に張り付いている並びは **クリア不可**。
- 縦並び条件：`SX(0)==SX(1)==SX(2)` かつ `|(SY(0)-SY(1)) * (SY(1)-SY(2)) * (SY(2)-SY(0))| == 2`。
  - 末尾の積=2 は「隣接3点（差が1,1,2 など）」の検査。
- 横並び条件：上記のX/Y入れ替え版。
- 条件成立で次面へ。`PLAY "T120S1M3000L8O5DE16E16DCDE16E16O6C4"` のクリアSEを鳴らす。

## ステージデータ

行1250〜の `DATA` 文。1ステージ＝`XM, YM, S1, MAP$` の4要素：
- `XM` = マップ幅（タイル数、奇数も含む）
- `YM` = マップ高さ
- `S1` = 許容ステップ数
- `MAP$` = 各セルを **3進2桁を1文字（0〜8）に圧縮した文字列**。
  - 復号: `L = MID$(MAP$, i+1, 1)`、`D$(L) = (L/3, L%3)` の2セル分。
  - `KS = 0/1/2`、`KS = 2` のセルは初期クリスタル位置として `SX/SY` に登録。

ステージ数は30面（行1250〜1540 のDATA）。

## グラフィック（行1080〜の CHR DATA）

3種のタイル（67 word 分 × 3）：
- `CR%` = クリスタル
- `BR%` = ブロック
- `MY%` = 自分（玉ねぎ）

オリジナルではMSXのVRAMにCOPYする16色ビットマップ。
移植時は **同じドット絵をPNG化** するのが素直。元データから16x16のインデックスカラー画像を一度抽出し、`public/sprites/` に置く想定。

## タイトル画面

- パレットアニメ（COLOR= で7色 → ランダム色をループ）。
- 大きな `CRYSTAL STORY` 文字を、8×8ドットの円形タイルを4分割したものを並べて描画（行180〜340）。
- `HIT ANY KEY` 表示後、キー入力でゲームへ。`C` でコンティニュー。

## サウンド

すべて PSG `PLAY` 文。Web Audio API の矩形波（OscillatorNode `type: 'square'`）で代用。
- 押し出し失敗SE：行1060
- ブロック破壊SE：行1070
- クリア音：行910

## エンディング（行940〜960）

`CONGRATULATIONS!` 表示後、`A` `1` キーで2人用 おまけゲーム（玉ねぎ同士のジャンケン or 並べ取り合い的なミニゲーム。行950〜970は不完全に見えるので要再確認）。

## 移植アーキテクチャ（JS版）

レイヤ構成案：

```
src/
├── main.ts            エントリ。requestAnimationFrame ループ
├── game/
│   ├── stages.ts      DATA を JSON 化したステージ定義
│   ├── board.ts       KS 相当の盤面、押し出しロジック、判定
│   ├── input.ts       キーボード＋タッチ
│   ├── render.ts      Canvas2D 描画（タイル＋ステータス）
│   ├── audio.ts       Web Audio で PSG エミュ
│   └── states.ts      title / playing / cleared / ending
└── assets/
    └── sprites.ts     CHR DATA を ImageData にデコード
```

実装の手順（次のステップ）：
1. CHR DATAをデコードして16x16のタイルをcanvasに描く（見た目を先に出す）。
2. ステージDATA 30面をパースし、board.ts に流し込む。
3. 入力 → 移動・押し出し → 揃い判定の最短ループを完成。
4. ステータス表示・タイトル・SE。
5. スマホ向けタッチUI。
6. おまけゲームは後回し可。

## 既知の未確定事項

- CHR DATAの色番号 → 実際の見た目の対応（パレット 0〜15）。BASIC冒頭の `A$="330440550660770020030040050060070222555"` で COLOR= による再定義をしているので、実機キャプチャの色を最終ソースにする想定。
- エンディング（行940〜970）の `LELSECOPYMY%` 周辺の挙動詳細。要 実行確認 or エミュ確認。
- `INKEY$` の `"a"` / `"1"` 判定が左右移動になっており、ジャンケンというよりは2人で位置取りするミニゲームに見える。実機確認推奨。
